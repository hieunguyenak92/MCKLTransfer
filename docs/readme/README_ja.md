# MCKL Transfer

**自分の端末へ、自分のやり方で。**

ブラウザーから使える、個人と小さなチームのためのセルフホスト型ファイル共有。

[最新版をダウンロード](https://github.com/hieunguyenak92/MCKLTransfer/releases/latest) · [設定ガイド](../CONFIGURATION.md) · [Star で応援](https://github.com/hieunguyenak92/MCKLTransfer)

**0.5.0 · Apache-2.0 · クライアントのインストール不要 · 実行時の npm 依存関係なし**

</div>

大きな動画をパソコンへ移す。家族の端末に資料を送る。チーム用の小さな受信箱を作る。MCKL Transfer は、手元の 1 台をファイル共有の拠点に変えます。ほかの端末はブラウザーで接続するだけ。MCKL のクラウドアカウントは必要ありません。

## 使いたくなる理由

| 機能 | できること |
|---|---|
| 再開できるアップロード | 一時停止、再試行、SHA-256 検証、応答消失後も同じ完了結果を取得 |
| 自分で選べる公開範囲 | 共有スペース、受信者別の inbox、メンバー限定のルーム |
| QR で招待 | 期限付き・1 回限りの招待と、任意のホスト承認 |
| フォルダーと一括取得 | 相対パスを保持し、選択したファイルをストリーミング `.tar` で取得 |
| 日常の使いやすさ | 検索、チャット、転送履歴、ファイルの自動削除期限 |
| 実験的な直接転送 | 受信者が同意した WebRTC セッション。経路を direct/relay として表示 |
| 負荷を制御 | ファイル数・端末別容量のクォータ、ダウンロード上限、タブ間のサーバー側リース |

## すぐに始める

ホストに Node.js **24.22.2 以降の 24.x**、または **26.13.0 以降の 26.x** を用意します。

```sh
git clone https://github.com/hieunguyenak92/MCKLTransfer.git
cd MCKLTransfer
npm start
```

`npm install` は不要です。[Releases](https://github.com/hieunguyenak92/MCKLTransfer/releases) からソースを取得しても起動できます。

1. ターミナルに表示された LAN URL を、別の端末のブラウザーで開きます。
2. 端末名と 6 桁のアクセスコードを入力します。
3. 共有先を選び、ファイルやフォルダーを送信します。

**別の管理者コード**はホスト管理者だけが使用します。管理画面では端末の承認・失効、招待、ルームを管理できます。

既定の HTTP は暗号化されません。管理された信頼できる LAN で使用し、それ以外は信頼された HTTPS やアクセスを制限した Tailscale/WireGuard を構成してください。インターネットへ HTTP ポートを直接公開しないでください。

## 共有も、個別の inbox も

- **共有スペース:** 承認済みのメンバーでファイルとチャットを共有。
- **個別 inbox:** 送信者、指定した受信者、信頼するホスト管理者だけがアクセス。
- **ルーム:** 管理者がメンバーを指定。権限は一覧だけでなく、取得やイベントにも適用されます。

招待ボタンで 10 分間の招待リンクと QR を作成します。招待は 1 回限りで、サーバー再起動後には残りません。初回接続に承認を必須にする場合:

```sh
REQUIRE_APPROVAL=1 npm start
```

転送が切れたら同じファイルを選び直して再開します。同じ端末 Cookie と未失効のアップロードが必要です。リースは同一アップロードを複数タブが同時に変更することを防ぎます。

ホストへのアップロード完了と、受信端末での保存完了は別の状態です。対応ブラウザーの検証付き保存は、書き込みと SHA-256 の確認後に受領記録を送ります。

## WebRTC による直接転送 — 実験的機能

両方の端末がオンラインなら、ホストにファイルを保存せずに送れる直接セッションを選べます。

1. 人を指定し、直接転送するファイルを選択。
2. 受信者が承諾し、保存先を選択。
3. **両端末に表示された確認コードを別の信頼できる方法で比較し、両方で確認。**
4. データを小さな単位で書き込み、サイズと SHA-256 を検証。

HTTPS または localhost が必要です。受信側は `showSaveFilePicker` に対応したブラウザーが必要で、主な対象はデスクトップ Chromium です。ファイル全体を Blob として RAM に蓄積しません。未対応端末や接続失敗時は、明示的にホスト経由を選べます。保存場所や公開範囲を変えるフォールバックは自動で隠しません。

既定では外部 STUN/TURN を設定しません。必要なら `ICE_SERVERS` に自分で管理するサーバーを指定します。relay 表示は TURN 経由を意味し、常に直接経路になる保証はありません。[設定](../CONFIGURATION.md)を参照してください。

## データと信頼の境界

ホスト経由のファイルとチャットはホストが読めます。個別 inbox はアクセス制御であり、ホストに対する E2EE ではありません。直接転送の暗号化とコード確認も、悪意あるホストが配布する JavaScript から利用者を保護する仕組みではありません。

携帯端末では転送中のページを開いたままにしてください。PWA はバックグラウンドや iPhone の画面ロック中の転送を保証しません。リモートデスクトップ機能は含みません。

## 運用とアップグレード

- `SHARE_DIR` は非公開のデータディレクトリです。容量・ファイル数・期限・HTTPS・ICE の詳細は[設定ガイド](../CONFIGURATION.md)。`.env` は自動では読み込みません。
- 更新前にサーバーを停止し、データディレクトリ全体を保護してバックアップします。同じディレクトリを使用する 2 台目のホストプロセスはロックで拒否されます。
- 正常な停止・再起動では端末セッションを保持します。不正終了後は安全側に倒して再ペアリングが必要です。以前の所有権に関する復旧は管理者が行います。
- 自動削除期限はセキュア消去やバックアップからの削除を保証しません。ネットワークドライブや停電耐性を一律には保証しません。

速度はネットワーク、ディスク、ハッシュ計算、端末に依存します。測定条件と検証範囲は[検証記録](../VALIDATION.md)に記載し、loopback の数字を LAN の保証値として扱いません。

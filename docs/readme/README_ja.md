# MCKL Transfer

</div>

LAN 内の自分のサーバー、またはアクセスを許可したオーバーレイネットワーク内の端末間で、ファイルとチャットを共有します。Node.js が必要なのはサーバーだけです。他の端末はブラウザーで接続します。MCKL のクラウドアカウント、アクセス解析、データベース、実行時の npm 依存関係はありません。

**0.2.0-alpha.2 · Apache-2.0 · 実験版。** 導入前に[検証結果](../VALIDATION.md)と[セキュリティモデル](../../SECURITY.md)を確認してください。安定したサポートや、すべての端末での LAN 転送速度は保証しません。

## 信頼できるネットワークですぐに使う

セキュリティ修正を適用した Node.js **24（24.22.2 以降）**、または **26（26.13.0 以降）**をインストールします。ソースのディレクトリで次を実行してください。

```sh
npm start
```

`npm install` は不要です。ターミナルに LAN アドレス、6 桁のアクセスコード、**別の管理者コード**が表示されます。他の端末で LAN アドレスを開き、端末名とアクセスコードを入力します。管理者コードはサーバー管理者だけに渡してください。コードは localhost を含め、API からは取得できません。

既定の HTTP 接続は暗号化されません。自分が管理するネットワークで、信頼できる参加者とのみ使用してください。それ以外では HTTPS またはアクセスを制限したオーバーレイを使用します。このポートをルーターからインターネットへ転送しないでください。

### 使い方

- 複数のファイルを選択、またはドラッグします。アプリ全体のキューで最大 2 ファイルを同時に転送でき、速度、残り時間、一時停止、再開、再試行、キャンセルを利用できます。
- 接続が切れた後やページを再読み込みした後は、同じファイルを選び直して再開します。端末の Cookie が残り、アップロードの有効期限が切れていない必要があります。ページを閉じた後、ブラウザーはファイルの読み取り権限を自動では保持しません。
- **サーバーごとに、転送用タブは 1 つだけ使用してください。** 同じオリジンのタブは Cookie と再開情報を共有します。2 つのタブで同じアップロードを再開すると、一方でのキャンセルが他方の未完了データを削除する場合があります。元のファイルは安全ですが、残りのタブでは `404` 発生時に最初から送り直す必要があります。このアルファ版は、タブ間のアップロード所有権を調整しません。
- 送信前にブラウザーが元のファイルを読み取って SHA-256 を計算し、各チャンクと完成したファイルをホスト側で照合します。ハッシュ計算には追加の読み取りが必要なため、性能の低い端末では時間がかかる場合があります。ファイル全体を RAM に保持することはありません。
- 完了したファイルは共有一覧に表示され、ログイン済みの全メンバーがダウンロードできます。メンバーが削除できるのは自分の送信ファイルだけです。管理者は全ファイルの削除と端末セッションの失効ができます。
- 共有チャットは直近 200 件までを RAM に保持し、ホストの再起動で消去されます。特に携帯端末では、転送中にページを開いたままにしてください。PWA はバックグラウンド転送や、iOS の画面ロック中の継続を保証しません。

構成は **ブラウザー A → ホストに保存 → ブラウザー B がダウンロード**です。「アップロード完了」はホストが受信して検証したことを表し、B がダウンロードして保存したことを意味しません。ホストはファイルとチャットを読めます。E2EE や受信者別の個室はまだありません。

## 言語

アプリの表示言語は Tiếng Việt（ベトナム語）と English（英語）です。ページ上部の言語セレクターで変更でき、選択はこのブラウザーに保存されます。初回はブラウザーの言語に合わせて選び、対応していない場合は English を使用します。言語を変更してもページは再読み込みされず、ファイル転送も中断しません。ファイルの内容、チャット、端末名は翻訳されません。README はページ上部のリンクから 7 言語で読めます。

## 設定

アプリはプロセスの環境変数を読み取ります。`.env` は自動で読み込みません。容量の単位はバイト、時間はミリ秒です。

| 変数 | 既定値 | 意味 |
|---|---|---|
| `HOST`, `PORT` | `0.0.0.0`, `8787` | 待ち受けインターフェースとポート。既定は IPv4 |
| `SHARE_DIR` | ソースの隣の `./shared` | 非公開のデータディレクトリ。リポジトリの外を推奨 |
| `DEVICE_NAME` | ホスト名 | ログイン後とターミナルだけに表示するホスト名 |
| `SHARE_CODE` | 起動ごとのランダムな 6 桁 | メンバー用コード。互換性のため `LAN_SHARE_CODE` も受け付ける |
| `ADMIN_CODE` | 起動ごとの別のランダム値 | 最低 24 文字。秘密にすること |
| `MAX_FILE_SIZE` | `21474836480`（20 GiB） | ファイルごとの上限 |
| `MAX_TOTAL_SIZE` | `107374182400`（100 GiB） | 完了ファイルと、予約済みアップロード容量の合計 |
| `MIN_FREE_SPACE` | `134217728`（128 MiB） | ディスク空き容量の予備。OS のディスククォータではない |
| `CHUNK_SIZE` | `4194304`（4 MiB） | アップロードチャンクのリクエスト 1 件につき最大 16 MiB |
| `MAX_CONCURRENT_UPLOADS` | `4` | サーバーで同時に実行するアップロードの書き込み・ハッシュ処理数 |
| `MAX_PENDING_UPLOADS` | `128` | 保持する未完了アップロード数 |
| `UPLOAD_TTL_MS` | `86400000`（24 時間） | 未完了アップロードの作成時点からの絶対有効期限 |
| `SESSION_TTL_MS`, `MAX_DEVICES` | `43200000`（12 時間）, `128` | 通常セッションの期限と端末セッション総数。記憶した端末の期限は 30 日 |
| `REQUEST_TIMEOUT_MS` | `1800000`（30 分） | リクエスト 1 件の受信期限。60 秒間通信がないソケットは切断 |
| `TLS_KEY_FILE`, `TLS_CERT_FILE` | 未設定 | 直接 HTTPS 用の PEM 秘密鍵と証明書の組 |
| `PUBLIC_URL` | 未設定 | プロキシの外部オリジン。例：`https://transfer.example.org`。パス・クエリ不可 |
| `ALLOWED_HOSTS` | ローカルのホスト名・インターフェース | 追加する具体的なホスト名・IP をカンマ区切りで指定。ワイルドカード・ポート不可 |

専用のデータディレクトリを使用する PowerShell の例：

```powershell
$env:SHARE_DIR = "D:\MCKL-data"
$env:DEVICE_NAME = "Home transfer host"
npm start
```

再起動後にコードが変わっても、発行済みセッションは失効しません。端末管理画面で失効させてください。PIN が漏れた場合は PIN を変更し、**さらに**信頼できないセッションを失効させます。Cookie とファイル所有権は再起動後も保持されます。ログアウトや Cookie 削除後にペアリングし直すと、新しい識別情報になります。管理者は以前のファイルも削除できます。

## HTTPS と別ネットワークからの接続

### 直接 HTTPS

使用するホスト名・IP と SAN が一致し、すべての端末が信頼する CA の証明書を用意します。鍵をソースの外に置き、読み取り権限を制限して、両方の変数を設定します。

```sh
TLS_KEY_FILE=/secure/mckl/server.key TLS_CERT_FILE=/secure/mckl/server.pem npm start
```

対応する `https://...` URL を開きます。証明書の検証エラーを無視しないでください。自己署名証明書では、信頼できる経路で CA の信頼設定やフィンガープリント確認を行う必要があります。アプリには自動的な証明書ペアリングはありません。HTTPS の Cookie には `Secure`、`HttpOnly`、`SameSite=Strict` が付きます。

### Tailscale または WireGuard によるプライベートグループ

各端末にオーバーレイを導入し、正しいメンバーに権限を付与して、サービスのポートを制限します。MCKL の認証も維持してください。WireGuard では鍵、ルーティング、ファイアウォール、DNS を自分で管理します。Tailscale ではポリシーと direct/relay 経路を確認してください。プライベート IP アドレス帯であることだけでは、端末の信頼性は証明されません。

tailnet で HTTPS を使う選択肢として [Tailscale Serve](https://tailscale.com/docs/features/tailscale-serve) があります。ホストの DNS 名を取得し、tailnet の HTTPS を設定した後、対応するオリジンを指定して MCKL をループバックだけで起動します。

```sh
HOST=127.0.0.1 PUBLIC_URL=https://YOUR-HOST.YOUR-TAILNET.ts.net npm start
```

別のターミナルで次を実行します。

```sh
tailscale serve --bg http://127.0.0.1:8787
tailscale serve status
```

Serve が発行した正しい HTTPS URL を開きます。このサービスは tailnet 向けです。アクセス制御ポリシーを制限してください。条件と停止方法は [Serve CLI](https://tailscale.com/docs/reference/tailscale-cli/serve) を参照してください。MCKL は Tailscale のインストールや設定を自動では行いません。このリリースでは実際の tailnet 上での検証は行っていません。

他のリバースプロキシでは、ストリームと SSE をバッファーせずに転送し、Host を維持するか `PUBLIC_URL` を正しく設定します。適切なタイムアウトとリクエスト本文の上限を設定し、上流への接続を信頼できるプロキシだけに制限してください。アプリは接続の安全性の判定に `X-Forwarded-*` を信頼しません。

## データ、アップグレード、バックアップ

ホストは `SHARE_DIR` に `.mckl-manifest.json`、`.mckl-devices.json`（セッショントークンのハッシュ）、`.mckl-uploads.json`、`.mckl-objects/` を保持します。新しいペイロードは ID で保存し、表示名はマニフェストに記録します。サーバー稼働中は内部ファイルを編集・削除しないでください。同じ `SHARE_DIR` で 2 つのプロセスを実行しないでください。

ホストを停止してから、データディレクトリ**全体**をバックアップします。バックアップにはグループのファイルとアクセス権が含まれるため、保護が必要です。このアルファ版は有効な通常ファイルを参照する旧 MVP マニフェストを読み取れますが、古いペイロードをオブジェクトストレージに自動移行しません。所有者のない旧ファイルを削除できるのは管理者だけです。アップグレード前にバックアップしてください。新しいマニフェスト形式で書き込んだ後のダウングレードはサポートしません。

厳格な ACL を設定した、信頼できるローカルファイルシステムだけを使用します。期限切れの未完了アップロードは削除されますが、完成ファイルは自動削除されません。ネットワークドライブ、データディレクトリのクラウド同期、実際の停電、ストレージ機器の障害は検証していません。アトミック rename/fsync は、あらゆる破損を防ぐ保証ではありません。

## 他の端末から接続できない場合

ターミナルに表示された IPv4 LAN URL を選び、同じ Wi-Fi を使用し、ゲストネットワークや AP isolation を避けてください。ファイアウォールは必要なネットワーク・端末だけにポートを開けます。例のアドレスを置き換えて、別の端末からヘルスチェックを実行します。

```sh
curl --connect-timeout 5 http://192.168.1.10:8787/api/health
```

正しい応答は `{"ok":true}` です。タイムアウト時は通常、ルーティングやファイアウォールを確認します。`403` の場合はホスト名・Origin と `ALLOWED_HOSTS`/`PUBLIC_URL` を確認してください。解決のためにワイルドカードを追加しないでください。ブラウザーがローカルネットワークへのアクセス許可を求める場合があります。

## 開発、テスト、リリース

```sh
npm run check
npm test
npm run release:check
npm run release:source
```

ソースエクスポーターは許可リストのファイルだけを取り込み、アーカイブを再検証し、SHA-256 を `release/` に出力します。使用中のディレクトリ全体を ZIP にしないでください。`.gitignore` は Finder の ZIP からファイルを除外せず、コミット済みデータも削除しません。誤って npm に公開しないよう `private: true` を維持してください。ソースのライセンスは引き続き Apache-2.0 です。
